# Plumbers on Call CORP — website

The visual rules every page is checked against are in [DESIGN.md](DESIGN.md).

Marketing site for Plumbers on Call CORP (residential & commercial plumbing, Greater Boston, 24/7).
Next.js 16 App Router · React 19 · TypeScript · CSS Modules · three.js for the 3D world.

## The idea: "True to the line"

One persistent 3D world sits behind every page. A single brass line runs through dark stone; each page is a place along it, and changing page moves the camera along the line.

| Page | Place | Scene file |
| --- | --- | --- |
| Home | The Name: the official logo on a lit ivory slab | `world/scenes/name.ts` |
| Services, service pages | The Section: a building in cut-away, one room per service | `world/scenes/section.ts` |
| Our Work | The Plates: photographs on stone fins | `world/scenes/plates.ts` |
| About | The Plumb: a brass plumb bob with real pendulum motion | `world/scenes/plumb.ts` |
| Contact | The Valve: a slot of light and a quarter-turn valve | `world/scenes/valve.ts` |

- `world/layout.ts` is the map (where everything stands). `world/engine.ts` owns the renderer, camera poses per route, page-to-page travel and the intro. `world/materials.ts` is the shared material set.
- `components/world/WorldCanvas.tsx` loads the engine after first paint, picks a tier and intercepts internal links so the camera starts moving before the page changes.
- Tiers: **full** (desktop), **lite** (phones / low-power), **static** (no WebGL, reduced motion, data saver, or `?world=off`): a flat backdrop, and the pages show ordinary images instead.
- Pages talk to the world through DOM hooks: `data-world-anchor="sign"` (where the camera frames the logo on Home), `data-world-step="<n>"` (which room or plate is in view) and `signalWorld()` (Contact opens the valve).
- **Blender bake (Services building):** the building's static geometry is exported from the running site, taken through Blender (`scripts/bake-world.py`: bevelled edges, soft contact shadows baked into vertex colours, meshes merged per material, Draco-compressed) and saved as `public/world/baked/section.glb`. The site swaps it in when it loads and falls back to the code-built version if the file is missing (`?baked=off` forces that). The tub, boiler, tankless heater, storage tank and main shut-off valve are modelled in Blender (`scripts/fixtures.py`) and dropped in during the bake; the simple shapes in `section.ts` marked with `k.fixture(...)` are only stand-ins that show if the baked file is missing. To re-bake after changing `world/scenes/section.ts`: in development run `await __world.exportBakeable()` in the browser console to get the source `.glb`, then `blender -b -P scripts/bake-world.py -- <in.glb> public/world/baked/section.glb`. The Draco decoder lives in `public/draco`.
- **Third-party assets (all CC0, from Poly Haven):** `public/world/env/studio.hdr` (the "Ferndale Studio 07" lighting map, downscaled, used for reflections). No attribution is required.
- **Marble:** `public/world/tex/marble-*.webp` is our own black marble with gold veining, generated by `scripts/make-marble.py` in Blender (`blender -b -P scripts/make-marble.py -- <dir>`), then made seamless and converted to WebP by `node scripts/tile-marble.mjs <dir>`. It is mapped by world position (`world/materials.ts`), so every wall on every page carries the same veining at the same scale; `stoneHoned` is the same marble without mirror reflections, for floors, ceilings and fins.
- **Floor, strips, dust (in `world/scenes/name.ts`):** on the full tier the floor is a real planar mirror (three's `Reflector`); warm light strips run under the logo slab and along the wall base; a few hundred dust motes drift in the light.
- **Imagery:** the fixture images in `public/images/renders` are our own path-traced renders of the 3D building (`scripts/render-fixtures.py`, about two minutes each on CPU). They replace the earlier stock photos and are still labelled "Illustrative". Real project photos go in `content/projects.ts`.
- **Post-processing (full tier only):** bloom and a light film grain, using three.js's own EffectComposer passes. Tunables are at the top of `world/engine.ts`.
- The intro plays once per browser session on the homepage and can be skipped. In development, `window.__world` exposes the scene and `tick(n)` for inspection.
- Every word on the site is ordinary server-rendered HTML above the canvas; the canvas is decorative.

## Logo

`public/brand/logo.webp` is the official logo exactly as supplied (black lettering with gold edges), with only its ivory background made transparent by `scripts/prepare-logo.mjs`. It is always shown on ivory stone: the 3D slab on Home and a small ivory plate in the header, menu and footer. It is never recoloured, redrawn or mirrored.

## Where things live

| --- | --- |

| `components/site` | Header (desktop nav + `<dialog>` mobile menu), Footer, MobileCallBar, Logo plate. |

| `components/ui` | Shared primitives: PageHero, CtaBand, SiteImage, TrackedLink, Icon, JsonLd, RevealObserver. |
| `components/forms` | InquiryForm (client). |

## Routes

`/` · `/services` · `/services/{boilers-heating, water-heaters, bathroom-plumbing, residential-plumbing, commercial-plumbing, emergency-plumbing}` · `/work` · `/work/[slug]` (real projects only) · `/about` · `/service-areas` · `/contact` (`?service=<slug>` preselects the service) · `/privacy` · 404.

## Contact form and booking

- The form renders **only** when both `RESEND_API_KEY` and `INQUIRY_TO_EMAIL` are set (see `.env.example`). Without them, `/contact` shows phone + email instead, so the site never shows a form that cannot deliver.
- Delivery: `POST /api/inquiry` → validation (same rules as the client) → honeypot + minimum fill time → Resend REST API. Logs never contain customer details. Rate limit is best-effort, per server instance.
- Works without JavaScript: the browser posts the form and is redirected back to `/contact?status=…`.
- To enable: create a Resend account, verify the sending domain (`plumberoncallcorp.com`), then set in Vercel → Settings → Environment Variables:
  - `RESEND_API_KEY`
  - `INQUIRY_TO_EMAIL` (where requests should arrive)
  - `INQUIRY_FROM_EMAIL` (e.g. `Website <requests@plumberoncallcorp.com>`).
- **Housecall Pro:** paste the verified online-booking URL into `company.bookingUrl`. "Book online" buttons appear automatically (closing CTA and contact page).

## Analytics

`lib/analytics.ts` forwards `phone_click`, `request_service_click`, `booking_click`, `inquiry_submitted` and `inquiry_failed` to `window.dataLayer` / Vercel Analytics **if** either is installed. Nothing is loaded today. If you add an analytics tool, update `/privacy` first.

## SEO

Per-page titles, descriptions, canonicals and Open Graph (`lib/seo.ts`). JSON-LD: `Plumber` on every page (verified facts only, no street address), plus `Service` and `BreadcrumbList` on service pages. `sitemap.xml` and `robots.txt` are generated from content. No thin city pages: add confirmed towns to `app/service-areas/page.tsx`.

## Deploy (Vercel)

Production is the existing Vercel project serving `plumberoncallcorp.com` (see `DEPLOYMENT.md` for domains/DNS — **no DNS changes are needed** for this redesign).

1. Push the branch and open a pull request → Vercel builds a **preview** URL (if the project is Git-connected; otherwise `npx vercel` from the branch creates a preview).
2. Review the preview on desktop and phone.
3. Set the environment variables above if the form should go live.
4. Merge to `main` (or `npx vercel --prod`) to publish.
